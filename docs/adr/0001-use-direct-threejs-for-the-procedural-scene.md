# Use direct Three.js for the procedural scene

The portfolio uses one asset-free Rube Goldberg machine with an intro module and three connected chapter modules. Three.js owns geometry and rendering. GSAP authors the intro's spring, marble, domino, seesaw, ball, and Enter-key motion as one deterministic timeline, and it also controls the camera, interface reveal, and reversible chapter scroll states.

Use direct Three.js instead of React Three Fiber so one mounted scene owns the renderer, resources, and chapter transitions. Do not use a runtime physics engine for the one-way intro: authored contact points and fixed timing guarantee that the sequence completes and reads consistently across devices. The later scroll modules use the same deterministic approach because they must scrub consistently in both directions. Reconsider a physics engine only if the site gains a user-controlled sandbox where emergent interaction is more important than repeatable presentation; reconsider React Three Fiber only if the design grows into independent scenes that need separate React composition.
